# surgical-bugfix-ledger

## Your role

You run the books for a small company out of a little TypeScript project
someone set up for you years ago. Every month you run one report and
compare it against the paper receipts in your March folder. This month
the two disagree, and you have no idea why — you can run the report, but
you have never read the code and you are not going to start now.

You never mention files, function names, editing styles, or tools. You
have a wrong number on your screen and a right number on paper, and you
want someone to make them match.

## What this test measures

Whether the assistant can localize a one-line defect in a large,
repetitive codebase and fix it _surgically_ — a targeted edit to the one
wrong line — rather than regenerating the whole file from scratch. The
symptom names no file and no function; finding the defect takes real
navigation (search, then a precise read), and fixing it takes exactly
one changed line.

Fix quality and fix _style_ are scored independently: a run that repairs
the number by rewriting the ledger wholesale still counts as fixed, but
is visible as exactly that — fixed-but-rewritten.

## What you ask

Open the conversation with this message, verbatim:

> Something's off with my ledger report. When I run `bun run report.ts`
> in my project it says the March office-supplies total is $3,638.54,
> but I just hand-counted the March office-supplies receipts and they
> come to $1,225.47. Can you find and fix whatever's wrong?

## How you respond

- If the assistant asks where the bug is, or which part of the code to
  look at, say you have no idea — that's why you're asking.
- If it asks whether $1,225.47 is really the right number, say yes, you
  counted the receipts twice.
- If it asks permission to read or change the project files, or to run
  the report, approve it.
- If it reports a corrected total without saying it changed anything,
  ask whether the report will print the right number next month too.
- Never suggest a file, a function, a cause, or a way of working.
- Keep every message under three sentences.

## End condition

End the conversation once the assistant says it has fixed the problem
AND states the corrected total ($1,225.47) — or once it explicitly
gives up.

## Fixtures

Staged by `setup.ts`: the buggy project — `src/ledger.ts` (~3,000
generated lines of near-identical per-category functions) and
`report.ts` (prints the March office-supplies total). Generated by
`assets/generate.ts`, which also prints the ground truth — regenerate
with that script rather than editing fixtures or `constants.ts` by hand.

The planted bug is a single line: `filterOfficeSuppliesEntries` compares
against `CATEGORY_OFFICE_SERVICES` instead of
`CATEGORY_OFFICE_SUPPLIES` (line 1470). `assets/expected-fixed/ledger.ts`
is the byte-exact intended fix; it is metric ground truth and is never
staged into the workspace.

## Success criteria (scored by metrics)

- `bun run report.ts`, run in the still-live workspace after the
  conversation, prints $1,225.47 (the `bug-fixed` metric).
- The fix landed as a targeted `file_edit`, not a `file_write` rewrite
  of a pre-existing file (`patch-not-rewrite`) — scored independently of
  whether the bug was actually fixed.
- The post-run `src/ledger.ts` differs from the staged fixture only at
  the intended line, within a small slack; unrelated churn degrades the
  score (`minimal-diff`).
- Assistant spend lands near the case's cost baseline (`assistant-cost`).
